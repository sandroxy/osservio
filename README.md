# Osservio

[English](README-EN.md)

Osservio 致力于为多平台宿主 App 提供应用内调试与诊断能力，覆盖开发联调、测试验收、正式运行中的现场排障，以及故障发生后的信息回溯。

目前可从源码接入 Android 与 iOS，包含日志、HTTP、WebSocket、运行环境、问题快照、故障证据恢复与原生查看界面，尚未发布 SDK 制品。两端的系统采集范围与前提条件不同，详见[原生能力覆盖](doc/native-capabilities.md)；React Native、Uni 和 Flutter 适配尚未实现。

## 当前可用

- 宿主主动写入分级、分类的文本日志，明确选择公开文本或替换为 `[private]` 的私密文本。公开分类不代表自动识别并删除敏感信息。
- 默认关闭、宿主可指定初始值和自动关闭时限的调试开关，单条文本和写入速率限制，以及按条数和 UTF-8 文本字节数共同约束的内存历史。
- Android 原生 View 与 iOS UIKit 查看器，统一为日志、网络、问题、应用四个入口。支持组合筛选、分层详情、按需正文阅读与搜索；语言默认简中、可切换英文，主题默认浅色、可切换深色，均独立于宿主。详见[原生查看器说明](doc/inspector.md)。
- 采集与界面生命周期独立：关闭查看器不停止采集，停止采集不清空日志。
- 完整的 JSON 日志与网络正文支持按层级展开、语法着色、搜索、原文切换及复制。保留原始数字与字段顺序；截断、无效或超出结构阅读预算的内容仍可查看原文。网络详情固定进入时的记录，返回列表重进可查看最新保留状态，不提供容易混淆为重试的刷新动作。
- 两端均提供默认隐藏的应用内悬浮入口，由宿主决定何时显示。全屏查看时，可从详情、筛选或编辑页收起，重新展开后继续当前会话；草稿不会因此自动应用或保存。悬浮球支持拖动吸边，进程内保留阅读状态；释放会话或重启进程后不保留普通查看内容。隐藏界面停止刷新，不申请跨应用悬浮权限。
- HTTP 观察支持请求状态、隐私策略和独立正文预算；可选模块接入宿主的 OkHttp 客户端或 URLSession 数据请求。清空或淘汰记录后，迟到的响应不能将其恢复。原生网络界面支持搜索、状态筛选、详情和按需读取正文，明确展示截断、缺失及观察边界。
- 基础采集可记录有界运行线索与宿主标记；可选原生模块观察生命周期通知，并按需读取设备、宿主与内存信息。原生运行环境页支持快照刷新、线索搜索、详情、复制及独立的基础采集控制。可选择仅保存在内存，或用 SQLite 将标记为需要跨重启保留的线索有界留存；原生留存页按次运行浏览记录，支持搜索、详情、复制、存储状态查看，以及确认后删除留存记录。详见[运行上下文说明](doc/runtime-context.md)与[线索留存说明](doc/breadcrumb-storage.md)。

WebSocket 支持宿主主动上报，以及显式接入 OkHttp 与 URLSession 客户端，采用有界时间线与独立文本预算。原生界面支持按连接分组、浏览事件、筛选和按需查看正文。消息提交、排队、发送结果和关闭事件分别记录，不能据此断言对端已收到，详见 [WebSocket 观察契约](doc/websocket.md)。

宿主还可通过原生 API 或原生问题页主动保存问题快照，选择附带说明、环境信息、有界运行线索、日志、HTTP 和 WebSocket 记录，并在重启后浏览、搜索、复制或确认删除。点击标记时固定时间和近期记录窗口；网络正文默认不附带，首次勾选时按限额读取，之后再次勾选或保存重试沿用同一份结果。说明文字也默认不保存，主动勾选后按公开诊断内容处理，不会自动去除其中的敏感信息。快照独立管理留存数量、有效期与容量，详见[问题快照说明](doc/incidents.md)。可选导出模块可以把已固定的快照编码为元数据和正文分开的 JSON 文档，并异步打包为临时 ZIP 文件，保留原始时间、精确整数和缺失状态。文件准备支持取消和独立缓存限额。宿主向原生查看器提供导出器后，可在已保存的快照页主动打开系统分享面板；取消或关闭不会删除快照，也不影响采集。详见[导出说明](doc/incident-export.md)。

可选 Runtime 模块还提供系统诊断读取 API：Android 11 起可读取主进程的历史退出信息，iOS 14 起可读取系统已交付的 MetricKit 崩溃与卡顿摘要，并显式订阅新报告。只提取限定的数值及应用、系统元数据，保留报告时间范围和缺失状态。宿主可通过 API 显式保存到本地问题档案，在原生问题页查看、复制，并使用可选导出模块分享这些证据；系统记录与手动快照分别限制留存数量。批量恢复 API 可在一笔事务中保存符合条件的报告与有界处理标记，减少重复读取造成的重复记录；相同摘要不等于同一次故障。宿主可将启动读取和报告交付接入受采集开关控制的恢复流程，关闭采集会拒绝新批次，已接收的保存任务仍可完成。界面区分故障时间与报告读取时间，不把信号终止或卡顿直接判断为崩溃；系统不保证重启后立即交付报告。详见[系统诊断说明](doc/system-diagnostics.md)。

Android 12 起，还可从系统原生崩溃记录中提取受限的地址堆栈、ELF 构建标识、信号和线程信息，随退出记录留存、查看与导出；无需安装额外信号处理器。系统记录可能缺失或被覆盖，界面会区分不支持、不可用、无效和超出预算等状态。这部分不包含 Java 异常栈或 ANR 原始跟踪；地址还原函数名仍需要匹配的符号文件。详见 [Android 原生崩溃证据](doc/android-tombstone.md)。

可选 iOS `OsservioCrash` 模块支持显式安装致命信号记录器，并在后续启动中读取有界的待恢复文件。记录遵循基础采集与详细会话开关；安装与界面可见性独立。遇到调试器或其他处理器冲突时会明确拒绝安装，旧报告仍可读取。报告保留原始时间、信号、调用栈地址及二进制标识，可接入问题档案、恢复去重、原生查看和导出流程；地址尚未解析为函数名。它不覆盖 SIGKILL、看门狗或内存不足终止，也不提供原始 Objective-C 异常抛出栈。详见 [Apple 致命信号证据说明](doc/crash-evidence.md)。Java 侧模型支持同一份证据契约，不代表 Android 已具备对应的原生崩溃记录器。

目前不会自动截获系统日志或安装崩溃处理器，也没有全局网络拦截或框架适配器。网络观察只覆盖显式接入的方法，具体差异见[网络覆盖说明](doc/network-integration.md)。先打磨原生双端的核心能力与交互体验，再扩展 React Native、Uni 和 Flutter。

源码接入说明：[Android](native/android/README.md) · [iOS](native/ios/README.md) · [日志行为与限制](doc/logging.md) · [HTTP 观察契约](doc/http.md)。这些详细说明目前为英文。原生构建、自动化测试与设备体验验收是不同的验证层次；当前实现和默认资源限制不代表已经完成生产性能验证。

## 目标能力

- **实时调试**：查看、筛选和搜索原生日志、JavaScript／Dart 日志及错误；检查 HTTP 请求与响应、WebSocket 连接和消息。
- **运行环境**：查看设备、系统、宿主 App 和运行时信息，结合应用生命周期、页面标记与关键操作了解问题现场。
- **故障回溯**：在平台允许的范围内，保留崩溃、异常终止及其他重要故障的证据和必要上下文，供后续启动时查看。
- **问题记录**：手动标记问题，选择需要保留的诊断内容，并按需导出经过脱敏的问题档案。

目标接入范围包括 Android、iOS 原生应用，以及 React Native、Uni 和 Flutter 宿主。各平台的采集范围、前提条件与限制会分别说明，实际支持以经过验证的接入文档为准。

## 采集与查看

宿主负责初始化和入口控制。面板是否可见、是否正在采集、哪些内容需要留存，是分别管理的状态。

基础采集以受限的资源开销记录已配置的运行线索与诊断证据。调试开关独立控制普通日志和详细网络记录，默认关闭，宿主可为开发或测试环境显式设为开启。默认持续到主动关闭或进程结束，也可配置自动关闭时限；资源和隐私限制始终有效。开关不自动跨重启记忆，收起界面也不改变采集状态。

实时数据以有界窗口提供查看；需要跨启动保留的关键线索和问题档案采用独立的留存策略。请求、日志是否值得保留，取决于诊断价值和采集策略。被过滤、未采集或已淘汰的内容无法事后还原，界面需要明确说明这些情况。

应用内查看应能离线工作，无需依赖桌面工具、账号或诊断服务器。截图、修改请求等额外能力需要独立启用，并明确告知其影响。
